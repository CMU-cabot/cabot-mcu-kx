# 実機CAN通信テスト

C++単体テストとは別です。SocketCANが利用できる実機ホストで実行し、
実際のハンドルMCUとCAN通信します。Python標準ライブラリだけを使います。
`tools/can_update.py` と同じリポジトリ配置を維持してください。

読み取りのみ（バージョン、3秒間の位置・センサー応答）：

```sh
python3 tests/hardware/can_smoke_test.py \
  --interface can0 --expected-version <書き込んだバージョン> \
  --output /tmp/handle-passive-test
```

動作確認も行う場合（ハンドル周囲が空いている状態で実行）：

```sh
python3 tests/hardware/can_smoke_test.py \
  --interface can0 --expected-version <書き込んだバージョン> \
  --motion-cycles 30 --output /tmp/handle-motion-test
```

- 外部からサーボ指令を受信した場合は失敗として停止し、その制御を上書きしないため中央復帰指令も送りません。
- OFFを送信して150 ms後、ONと目標位置を続けて送ります。
- 目標は1900と2200を交互に指定し、1.5秒後の末尾5サンプルが±20以内なら到達と判定します。
- 0x080/0x089/0x09A/0x481のDLC、40–60 Hz、受信サンプル間の最大200 msの間隔を確認します。
- 動作試験後は中央2047・ONへ戻し、位置応答を確認します。競合する制御プログラムを停止した環境で実行してください。
- `frames.jsonl` に送受信フレームと単調時計の時刻、`summary.json` に判定を保存します。
  出力ディレクトリは新規作成のみで、過去の結果を上書きしません。
- これは位置フィードバックによる動作判定です。指示器の機械的接続や目視による確認の代わりにはなりません。

書き込みは既存 `tools/can_update.py` の別操作です。転送CRC成功と、
このテストでの起動・通常通信・動作成功を混同しないように記録します。
このテスト自身はFlash書き込み、電源操作、障害注入を行いません。

## 14号機での実行結果（2026-10-26）

[保存した判定結果](results/ais-k25-14-8e07d60.json)

- ファームウェア `8e07d60464f8`、51,232 bytes、CRC32 `5b7c7af6`。
- CAN書き込みを3回実施し、全回でCRC検証・起動後のバージョン・通常通信を確認。
  2/3回目の転送所要時間は14.156秒／14.167秒。
- 最初の書き込み後30回、3回目後4回のOFF→ON・目標到達がすべて成功。
  目標1900/2200に対し終端位置1903/2197。終了時の中央復帰位置は2050。
- 通常通信は約50 Hz。観測後のCAN送受信エラーカウンタは0。
- 手動RESETや5V電源操作による復旧は不要。実機にはこの新版を残した。

転送に使ったのは既に実機で検証した `07a4067383c9` の
`tools/can_update.py`（1 ms間隔の送信と停止検出を含む）です。
最小修正版ブランチに残る旧転送実装の反復試験ではありません。
通信テスト自身はバージョン問い合わせだけに同モジュールを使います。

試験スクリプトの初回実行ではSocketCANフィルタのマスク設定により受信できず、
書き込み前の旧版チェックで失敗しました。通常フレームのフィルタを修正し、
旧版で約50 Hzの応答を確認してから上記の試験を実施しています。
競合送信者を検出した際に復帰指令を送らない処理は、30回試験後に追加し、
再書き込み後の試験ではその版を使用しました。競合送信の実機注入試験は未実施です。

結果はこの機体・小角度・試行回数に限定します。DynamixelのCRC原因、
長時間運転、他機体、リセット復帰やスタック残量を保証する試験ではありません。
